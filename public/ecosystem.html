The QuickBill Ecosystem

The QuickBill ecosystem combines a Windows desktop billing application with Android companion applications for barcode input and customer-facing display.

Overview

QuickBill is built around three focused applications:

  • QuickBill Desktop — the core Windows billing and POS application, and the authoritative source of billing data
  • QuickBill Barcode Scanner — an Android companion for barcode input
  • QuickBill Customer Display — an Android companion for real-time customer-facing bill and payment display

Companion applications connect to QuickBill Desktop. They do not replace the desktop application and do not act as independent billing systems.

Architecture

QuickBill Desktop is the central application. Companion applications provide input and display support around it.

QuickBill Desktop Windows · Core billing & POS · Source of truth
Barcode Scanner Android · Input companion
Customer Display Android · Customer-facing display

Source of Truth

QuickBill Desktop is the authoritative billing and payment system. It manages:

  • Products
  • Inventory
  • Cart state
  • Bills
  • Transactions
  • Payment state
  • Customer information
  • Invoice generation

Companion applications provide supporting functionality:

  • Barcode Scanner — provides barcode input to the desktop application
  • Customer Display — receives and displays billing and payment state from the desktop application

The Customer Display does not calculate or modify the bill. The desktop application remains fully functional if a companion application is disconnected.

Information Flow

Conceptual flow during normal use:

  1. Products and billing information are managed by QuickBill Desktop.
  2. Barcode scanning (USB scanner, camera, or the Barcode Scanner companion app) can provide product or barcode input to the desktop application.
  3. QuickBill Desktop processes the billing workflow: items, quantities, tax, discounts, totals, and payment.
  4. Customer-facing billing and payment state can be sent to the Customer Display.
  5. The Customer Display presents that state to the customer (items, totals, payment information, UPI QR, success state).

The desktop application remains the source of cart, bill, and payment state at every step.

How the Ecosystem Works During a Sale

  1. The operator works in QuickBill Desktop on a Windows PC at the counter.
  2. Products are added to the bill manually or through barcode input (USB scanner, camera, or the Android Barcode Scanner app).
  3. QuickBill Desktop updates the current bill: items, quantities, tax, discounts, and totals.
  4. If a Customer Display is connected, it shows the current bill items and totals to the customer in real time.
  5. The operator selects a payment method (Cash, UPI, Card, or Credit). For UPI, a dynamic QR can be generated and shown on the Customer Display.
  6. After payment is completed, QuickBill Desktop finalizes the transaction. The Customer Display can show the payment success state.
  7. Invoices can be generated and printed from the desktop application (A4 or 80 mm). Previous bills remain available in billing history.

01

QuickBill Desktop

The core Windows billing and POS application. It is the central system and the authoritative source of billing data.

Platform

Windows 10 / Windows 11

Role

Core billing and POS application · Source of truth

Responsibilities

  • Product management (add, edit, delete, search)
  • Inventory and stock management
  • Cart and bill state
  • Manual and barcode-based item entry
  • Tax and discount handling
  • Payment workflows (Cash, UPI, Card, Credit)
  • Dynamic UPI QR generation
  • Professional PDF invoice generation (A4 and 80 mm)
  • Bill history, search, and reprint
  • Hold and resume bills
  • Communication with companion applications

How it fits

All authoritative billing and payment decisions happen in QuickBill Desktop. Companion apps provide input or display support only.

02

QuickBill Barcode Scanner

A companion Android application that turns a phone into a dedicated barcode scanner and network camera for QuickBill Desktop.

Platform

Android 8.0 (API 26) or higher · Device with camera

Role

Input companion · Not a billing application

Capabilities

  • Android camera barcode scanner
  • Real-time barcode detection
  • Network camera streaming
  • QuickBill Desktop integration
  • Automatic IP address configuration
  • Continuous scanning
  • Duplicate scan prevention
  • Camera selection
  • Scanner settings and customization

How it fits

The Android device acts as a wireless barcode scanner for the desktop billing application. Barcode information is used by QuickBill Desktop for product lookup and billing. The scanner does not store or manage the authoritative bill.

The phone and Windows computer must be on the same local network. The displayed device/network address can be configured in QuickBill Desktop under Scanner Settings.

03

QuickBill Customer Display

A companion Android application that provides a real-time customer-facing display for bill items, totals, payment information, UPI QR, and payment success state.

Platform

Android tablet · Android 8.0 (API 26) or newer

Role

Customer-facing display companion · Not the source of truth

Capabilities

  • Real-time bill updates
  • Customer and cashier information
  • Itemized billing display (quantity, rate, amount)
  • Subtotal, tax, discount, and total
  • Cash, UPI, Card, and Credit payment display
  • Dynamic UPI QR display
  • Payment pending and payment success screens
  • Automatic return to welcome screen
  • Full-screen tablet interface
  • Automatic reconnection to QuickBill Desktop
  • Graceful disconnected state

How it fits

The Customer Display receives and shows billing and payment state from QuickBill Desktop. It does not calculate or modify the bill. QuickBill Desktop remains fully functional if the display is disconnected.

Connection uses WebSocket on port 8765. The tablet and desktop must be on the same local network.
